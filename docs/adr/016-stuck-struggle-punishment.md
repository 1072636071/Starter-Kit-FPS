# ADR 016: 建筑缝隙卡住采用"惩罚性慢推回"而非碰撞封堵

## 状态

已接受

## 背景

城市地图（GridMap，cell_size=4m）中的建筑模型（structure 7-11）不填满整个格子——模型几何有内缩（inset），相邻建筑之间形成 0.6m~1m+ 的缝隙。trimesh 碰撞忠实跟随模型几何，因此缝隙是物理上可进入的空间。玩家（胶囊体半径 0.3m、二段跳）可以跳入这些缝隙，但进入后两侧碰撞夹住胶囊体，水平移动被完全阻挡，卡死。

核心张力：是在碰撞层面**阻止进入**（方案 A：整格盒子碰撞），还是**允许进入但施加惩罚**（方案 B：卡住后慢推回）。

## 决策

采用**方案 B：惩罚性慢推回**。

玩家卡住后进入三态状态机（NORMAL → STUCK → ESCAPING → NORMAL）：

1. **STUCK 判定**：在地面 + 有 WASD 输入 + 水平速度 < 0.3 m/s + 持续 0.5s
2. **STUCK 状态**：禁止移动/跳跃，允许视角转动/射击，正常受伤。屏幕中下方显示"按 G 尝试挣扎离开"
3. **按 G（struggle 输入动作）→ ESCAPING**：沿进入方向反向以 0.5 m/s 匀速推出
4. **ESCAPING 终止**：`test_move` 前方无碰撞（脱离）或推出 8m（安全上限）→ 回到 NORMAL
5. **ESCAPING 不可取消**：按了 G 就锁定推回直到脱离
6. **死亡优先**：推回期间玩家死亡 → 死亡流程接管，取消推回

设计哲学：卡住本身是惩罚（暴露于敌人火力下的固定靶），而非需要被"修复"的 bug。

## 理由

- **保留探索感**：城市缝隙是视觉上的"可进入空间"，硬性封堵（整格盒子碰撞）会让建筑边缘变成不可解释的隐形墙
- **惩罚即反馈**：玩家通过被卡住学到"不要跳进缝隙"，比隐形墙更有游戏性
- **不改变碰撞管线**：trimesh 碰撞保持精确（玩家仍可走上建筑、利用掩体凹面），无需为建筑额外生成盒子碰撞
- **实现局部化**：仅修改 `player.gd` + HUD，不影响 GridMap/MeshLibrary/转换管线

## 替代方案

| 方案 | 描述 | 否决原因 |
|------|------|----------|
| A. 转换管线生成整格盒子碰撞 | 建筑格子额外生成填满 cell 的 BoxShape3D | 建筑边缘变成方形隐形墙，玩家不能贴凹面走；改变碰撞管线，影响 NavMesh 烘焙；视觉与碰撞不一致（看得到缝隙但走不进去） |
| C. 修改地图数据消除缝隙 | 调整布局让建筑不紧邻 | 牺牲城市密度感，工作量大，不保证新布局没有新缝隙 |
| D. Area3D 禁入区传送 | 进入时传送回 | 体验突兀，需大量 Area3D 节点，性能开销 |

## 参数汇总

| 参数 | 值 | 说明 |
|------|------|------|
| 卡住判定时间 | 0.5s | 有输入但无位移的持续帧数阈值 |
| 速度阈值 | 0.3 m/s | 低于此视为"无有效位移" |
| 推回速度 | 0.5 m/s | 正常行走 5 m/s 的 1/10 |
| 推回上限 | 8m | 2 个 cell，安全网 |
| 输入动作 | `struggle` / G 键 | 触发挣扎 |
| 无音效 | — | `sounds/` 下无合适素材 |
