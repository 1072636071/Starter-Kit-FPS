# ADR 007: 小地图采用动态俯视相机（SubViewport）方案

## 决策

小地图采用 **方案 A：动态俯视相机**——在场景高处放置第二台 `Camera3D` 垂直朝下，将其渲染进一个 `SubViewport`，再用 `ViewportTexture` 把渲染结果贴到 HUD 角落的 `TextureRect`。地图底图、玩家与敌人位置**全部由这次俯视渲染自动产生**，**不**使用静态底图 + 手动光点同步，也**不**复用导航网格可视化。

## 背景

当前世界是 GridMap（`city-level.tscn`，建筑/道路为 3D 瓦片），地图约 160m × 160m（边界墙在 x/z = ±80），中心在原点。玩家、怪物（`monster_melee`/`monster_ranged`，挂在 `Monsters` Node3D 下）都是世界中的真实 3D 节点。HUD 是 `CanvasLayer`（`scripts/hud.gd`），当前含准星、血条、右下弹药列表——是放置小地图 UI 的自然位置。

核心张力：小地图底图与实体位置，要么"自动从 3D 世界派生"，要么"手工维护一份 2D 表示"。两种路线决定了完全不同的代码结构与长期维护成本。

## 替代方案

| 方案 | 描述 | 否决原因 |
|------|------|----------|
| A. 动态俯视相机（**选中**） | 第二台俯视 `Camera3D` 渲染进 `SubViewport`，`ViewportTexture` 贴角落 UI | 与 GridMap 世界契合度最高，地形/敌人按真实坐标自动显形，几乎零手动同步；160m 小地图二次渲染开销可忽略 |
| B. 静态地图图 + 动态光点 | 预烘焙 2D 俯视图（或手绘），玩家/敌人用 `Control` 画成小圆点 | 需另做静态底图（City Builder 能导但跨项目、要维护两套世界表示）；渲染虽极便宜，但失去"建筑随地形立体可见"的导航价值，且敌人同步仍要代码 |
| C. 导航网格可视化 | 直接拿 `NavigationRegion3D` 的 navmesh 当底图 | 只显示"可走区域"，不含建筑细节，对 FPS 玩家不直观；与玩家期望的"地图"语义不符 |

## 影响

- HUD（`CanvasLayer`）角落新增一个小地图 UI 容器（圆形或方形 `TextureRect`），其 `texture` 绑定到 `SubViewport` 的 `ViewportTexture`。
- 场景（或玩家）新增一台俯视 `Camera3D`（建议正交投影 `orthogonal`），一台 `SubViewport` 承载该相机渲染；俯视相机通过 `cull_mask`/`layers` 控制"哪些节点进小地图"（例如隐藏玩家自身的第一人称武器模型，只显示世界与敌人）。
- 玩家与敌人位置**自动**出现在小地图中（因为是同一 3D 世界的真实节点），无需额外同步代码。
- 性能：每帧多一次俯视渲染。对当前简单网格 + 少量怪物可忽略；若未来地图变大，可降级为"降分辨率 SubViewport"或"限帧刷新"。
- 旋转策略、显示内容、形状/尺寸/缩放等子决策见后续 grill 会话，记录于 CONTEXT.md「小地图系统（Minimap）」。

## 后续决策（grill 会话补充）

| 子决策 | 选定方案 | 关键理由 |
|--------|----------|----------|
| **旋转** | **北朝上（north-up）**：俯视相机只跟随玩家 x/z 位置，朝向固定不转；玩家用朝向箭头（Player Blip）表示 facing | 地面永远稳定好读，无需玩家在脑中换算朝向；实现成本低（相机不转，仅同步位置）。被否决的 heading-up：虽"前方=地图顶"手感好，但地面跟着转会致部分玩家眩晕 |
| **显示内容** | 玩家（箭头）+ **两种敌人全显示**（红点，近战/远程用形状或深浅区分）；不显示目标/拾取物（项目暂无） | 小地图核心价值即"敌人在哪"，当前仅 4 只全显示零负担；用 minimap 图层标记而非怪物真实 mesh 顶视（顶视怪异）。被否决的"仅视线内敌人"：对 v1 是过度工程 |
| **形状与位置** | **圆形 + 右上角**；方 `SubViewport` 渲染经 `ShaderMaterial` 径向 alpha 遮罩裁成圆 | FPS 经典样式，圆形自动隐藏俯视四角畸变；右上避开血条(左下)/弹药(右下)。被否决的方形：零遮罩但观感不如圆形 |
| **缩放** | **全图覆盖（~160m）**：俯视正交相机半高 ~80m，固定俯视整个 160×160 世界，相机不随玩家移动 | 与"敌人全显示"零冲突，4 只敌人永远可见；实现最简（相机固定尺寸）。被否决的局部视野：需处理敌人出图，复杂度上升 |
| **图层过滤** | **2D 叠加方案**：俯视相机 `cull_mask = layer 1`（仅地形）；玩家箭头/敌人图标为 2D `Control` 叠加（非 3D 图层标记），每帧投影世界 (x,z)→UV 放置；敌人真实 mesh 从 layer 1 挪到 layer 3 以免顶视 blob；武器 viewmodel(layer 2) 天然不进图 | 图标样式可控、零图层泄漏风险、无需改主/武器相机 `cull_mask`。被否决的"3D 标记+专用图层"：需改两台相机 cull_mask 腾出仅小地图层，窗口改动更多 |
| **结构归属** | 世界侧（俯视相机+`SubViewport`）加进 `main.tscn` 的 `Main` 子节点（非 Player）；UI 侧（圆形 `TextureRect`+blip 层）加进 `HUD`（`CanvasLayer`）下的 `Minimap` `Control`；逻辑由新建 `scripts/minimap.gd` 驱动 | 世界节点属于关卡、UI 属于 HUD、逻辑独立脚本——职责单一。被否决的"全塞 hud.gd"或"autoload"：脚本膨胀 / 无必要 |
