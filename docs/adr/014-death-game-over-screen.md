# ADR 014: 死亡转为"游戏结束"界面（含战绩 + 重开）

## 决策

玩家 `health <= 0` 时本局结束：冻结游戏 → 显示 **Game Over 结算界面**（存活波数、击杀数、累计金币、达到等级等）→ 提供"重开一局"。重开即全新本局，全部本局状态（金币 / 经验 / 护盾 / 弹药 / 升级）重置。取代现有 `player.gd` 的 `get_tree().reload_current_scene()` 裸重置。

## 背景

`player.gd` 的 `damage()` 在 `health < 0` 时直接 `get_tree().reload_current_scene()`（瞬时重置、无界面）。肉鸽需要一局"有始有终"的反馈闭环（见 ADR 009 的 Arena Run 定义）。

## 替代方案

| 方案 | 描述 | 否决原因 |
|------|------|----------|
| **A. Game Over 界面 + 战绩 + 重开（选中）** | 死亡 → 结算界面 → 重开 | 给一局明确句号与战绩，肉鸽基础反馈闭环 |
| B. 即时重开无界面 | 保留 `reload_current_scene()` | 太粗糙，无反馈 |
| C. 结束 + 跨局元进度（meta-progression） | 死亡保留部分进度到下一局 | 进阶形态，用户未要求，v1 不做（留作未来扩展） |

## 影响

- 新增 **Game Over 界面**（UI 场景 / `Control`），展示本局战绩，提供"重开一局"按钮。
- 死亡时**冻结（pause）**而非 reload；重开重置全部本局状态。
- 需要在一局作用域内累积 **run stats**：存活波数、击杀数、累计金币、达到等级。
- 元进度（C）明确为 v1 之外，不在本次范围。

> 参见 [ADR 027](027-ui-modernization-design-system.md) — UI 现代化设计系统（游戏结束界面重构为 UITheme token + 阶梯式过渡动效）
