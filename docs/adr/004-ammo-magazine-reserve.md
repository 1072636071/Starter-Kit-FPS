# ADR 004: 弹药系统采用弹匣+备弹模型

## 决策

每把武器拥有两级弹药池：**Magazine（弹匣）**和 **Reserve（备弹）**。弹匣归零必须换弹才能继续射击，备弹归零该武器彻底无法使用。

## 背景

项目当前无弹药系统，射击仅受 cooldown 冷却限制，可无限开火。玩家需要：
1. 右下角显示弹药余量的 HUD
2. 不同枪械显示不同名字
3. 能看到所有枪的剩余弹药
4. 简单的换弹动作

## 替代方案

| 方案 | 描述 | 否决原因 |
|------|------|----------|
| A. 弹匣+备弹（**选中**） | 弹匣 + 备弹两级，弹匣打空需换弹 | — |
| B. 纯弹匣（仅弹匣，无限备弹） | 只有当前弹匣，打空自动补满 | "换弹动作"无实际意义；弹药管理维度缺失 |
| C. 仅总弹量 | 单一数字，无换弹概念 | 同 B，且"换弹动作"完全无法落地 |

## 影响

- `Weapon` 资源类需新增 `display_name`（String，武器显示名称）、`magazine_size`（int）、`max_reserve`（int）、`reload_time`（float）属性，均为 per-weapon 独立配置
- 两把武器中文名：blaster → "爆能枪"，blaster-repeater → "连发枪"
- 玩家 `player.gd` 需维护每把枪的 `current_magazine[]` 和 `current_reserve[]` 数组
- 射击逻辑需在扣扳机前检查弹匣 > 0
- 新增换弹按键和逻辑
- HUD 需新增弹药显示区域
