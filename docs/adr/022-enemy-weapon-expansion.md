# ADR 022 — 敌人角色化与武器扩展架构

> 状态：accepted
> 来源：grill-with-docs 会话，2026-07-25

## 上下文

当前项目只有 3 种泛化敌人（近战/远程/飞行）和 2 把枪（blaster/blaster-repeater），玩家很快会"见穿"所有内容。项目上游有同一 Kenney 系列的丰富素材未使用：
- `kenney_blocky-characters_20`（18 个类人角色，与现怪物同骨架/动画）
- `kenney_cube-pets_1.0`（24 个小动物，不同绑定）
- `kenney_blaster-kit_2.1`（40 个武器/Grenade/配件模型，约 20 把真枪 + 2 种手雷）

用户要求：
1. 所有敌人替换为具体角色，**每个敌人有独特机制**
2. 武器库大幅扩展，商店随机刷枪、宝箱概率掉，最多带 3 把
3. 弹药改为 6 种类型（手枪/步枪/霰弹/狙击/能量/榴弹），手雷独立槽
4. 多工单拆分、先规划后实施

丧尸与狂暴丧尸两个角色暂不纳入本次规划。

## 决策

### 1. 敌人架构：基类 + 可插拔模块

**选择方案 2（基类 + 可插拔特殊机制模块组合）。**

现有 3 个 `monster_xxx.gd` 子类的模式不做（18 个子类的耦合和冗余不可接受），也不做纯组件树（Godot 原生节点太重）。采取中间路线：

- `monster_base.gd` 保留现有 FSM + 避障 + 视线 + 跳跃导航 + 动画 + 受击/死亡框架。
- 基类新增 4 个模块钩子（`on_enter_state` / `on_tick` / `on_damage` / `on_death`），在对应时机遍历已挂载模块调用。
- 每个特殊机制实现为一个 `EnemyModule` 节点，挂为敌人的子节点。
- 新敌人 = 一个 `.tscn`（指定 GLB 模型 + `@export` 参数 + 挂 1–3 个模块节点），**不写新子类**。

#### 钩子定义

```gdscript
# monster_base.gd 中新增

var _modules: Array[Node] = []

func _ready():
    # ... 现有初始化 ...
    _collect_modules()

func _collect_modules():
    for c in get_children():
        if c.has_method("module_setup"):
            c.module_setup(self)
            _modules.append(c)

func _run_module_hook(method: String, args: Array = []) -> void:
    for mod in _modules:
        if mod.has_method(method):
            mod.callv(method, args)

# 在 _change_state(new_state) 末尾调用
#   _run_module_hook("on_enter_state", [new_state])
# 在 _tick_state(delta) 末尾调用
#   _run_module_hook("on_tick", [delta])
# 在 damage(amount) 中（减血前）调用
#   _run_module_hook("on_damage", [amount])
# 在 destroy() 中（_dead=true 后、died emit 前）调用
#   _run_module_hook("on_death", [])
```

#### 模块接口

```gdscript
# 所有模块的约定接口（非强制继承，用 has_method 检测）
# class_name EnemyModule extends Node

func module_setup(enemy: Node3D) -> void:  # 初始化，拿到宿主引用
func on_enter_state(state: int) -> void:     # 状态转换时
func on_tick(delta: float) -> void:          # 每物理帧
func on_damage(amount: float) -> void:       # 受击时
func on_death() -> void:                      # 死亡时
```

模块间**不互斥设计**：若两个模块同时尝试修改同一属性（如都改移速），按 `_modules` 数组顺序后覆盖前。特殊冲突由单个模块内部自己防御（如 Shield 模块在 `on_damage` 中吸收伤害后把 amount 置零，后续模块收到 amount=0）。

### 4. 武器系统

#### 弹药类型

每种弹药有明确的战略定位，决定其定价、稀缺度和适用场景：

| 弹药 | 定位 | 适用武器 | 设计意图 |
|------|------|---------|---------|
| 手枪弹 | **廉价通用** — 最便宜，伤害偏低，覆盖面广（4 把枪） | 手托手枪-小口径、重型手枪-大口径、微型冲锋枪、微型冲锋枪-双枪口 | 前期主力弹种，经济实惠，新手友好 |
| 步枪弹 | **中程主力** — 性价比最高，伤害中等，中后期泛用 | 突击步枪、短突击步枪-双枪口、机枪 | 万金油弹种，什么都能打 |
| 霰弹 | **近身爆发** — 贵但近程毁灭性，弹药稀缺 | 半自动霰弹枪、自动霰弹枪、4管霰弹枪、重型半自动霰弹枪 | 高风险高回报，近战王 |
| 狙击弹 | **远程点杀** — 最贵，单发伤害天花板，弹药极少 | 狙击步枪、狙击步枪-重型 | 精英/高价值目标杀手 |
| 能量电池 | **精准持续** — 中远程精准，部分枪无需换弹 | 能量突击步枪、双管能量枪、上下双枪口能量枪、持续射线枪、blaster、blaster-repeater | 科技感弹种，无弹道下坠 |
| 榴弹 | **AOE 清群** — 最贵，范围伤害，弹药极少 | 短柄榴弹发射器 | 紧急清场按钮，用一发少一发 |

**`Weapon` Resource 新增字段：**

```gdscript
@export var ammo_type: StringName = &"手枪弹"  # 新增
@export var weapon_cost: int = 30               # 新增：商店售价
@export var durability_max: int = 150           # 新增：最大耐久度（每扣一次扳机减 1）
```

旧 `gold_cost_per_bullet` 字段废弃（不再按"发"买备弹）。

#### 耐久设计原则

每把枪的耐久是独立设计的，而非套用统一公式。核心原则：

1. **固定消耗**：每次扣扳机 -1 耐久，无论弹丸数（霰弹齐射 = 1 耐久，双管能量双发 = 1 耐久）。简单、可预测。
2. **高射速枪需要更多总耐久**：机枪 280 发看似很多，但 0.08s 射速意味着只能连续开火 ~22 秒；手枪 200 发以 0.30s 射速可以连续开火 60 秒——机枪"烧得更旺、死得更快"。
3. **爆发型武器耐久收紧**：狙击步枪 50 发、重型狙击 35 发、4 管霰弹 70 发、榴弹 25 发——不是不能让玩家爽，而是每发都必须有"这一枪值不值得"的决策。
4. **耐久 = 决策压力**：耐久低的枪逼迫玩家思考"现在用还是留给精英/紧急情况"，耐久高的枪提供安全感但往往 DPS 不顶级。

各枪"连续开火可持续时间"一览（便于直觉感受）：

| 武器 | 耐久 | 射速 | 连续开火时间 | 感受 |
|------|------|------|:---:|------|
| 手托手枪 | 200 | 0.30s | **60s** | 慢慢打，能陪你很久 |
| 重型手枪 | 150 | 0.50s | **75s** | 节奏慢，寿命长 |
| 微型冲锋枪 | 240 | 0.12s | **29s** | 一梭子爽完就见底 |
| 机枪 | 280 | 0.08s | **22s** | 最猛的火力，最短的寿命 |
| 4管霰弹 | 70 | 0.80s | **56s** | 射得慢所以活得久，但每发都痛 |
| 狙击步枪 | 50 | 1.20s | **60s** | 节奏极慢，50 发够狙死一整波精英 |
| 重型狙击 | 35 | 1.80s | **63s** | 全游最强单发，35 发是认真的 |
| 短柄榴弹 | 25 | 1.50s | **38s** | AOE 一炸一片，25 发能用很久 |

#### 定价设计原则

武器价格综合考虑 **战斗力 + 弹药使用成本 + 稀缺性**：

1. **战斗力驱动**：DPS × 精度因子 × 弹匣续航力 → 决定基础价格区间
2. **弹药经济调节**：弹药便宜的枪（手枪弹 0.04g/发），定价可以激进（使用成本低，总持有成本不高）；弹药贵的枪（狙击弹 1g/发、榴弹 2.5g/发），适当压价（玩家买回去还要花大价钱喂弹）
3. **弹药成本是隐形成本**：一把 125 金的机枪（步枪弹 1.25g/s）+ 连续开火 10 秒的弹药费 = 137.5 金实际开销。一把 55 金的重型手枪（手枪弹 0.08g/s）+ 同样的弹药开销几乎可忽略。**便宜的枪可能更贵，贵枪可能更省。**

弹药成本速查：

| 弹种 | 金/捆 | 金/发 | 金/100 伤害（以该弹种代表枪计） |
|------|:---:|:---:|:---:|
| 手枪弹 | 1 | 0.04 | 重型手枪 0.10g |
| 步枪弹 | 2 | 0.10 | 突击步枪 0.45g |
| 霰弹 | 3 | 0.38 | 半自动霰弹 0.78g |
| 狙击弹 | 4 | 1.00 | 狙击步枪 1.25g |
| 能量电池 | 3 | 0.25 | 能量突击步枪 1.00g |
| 榴弹 | 5 | 2.50 | 短柄榴弹 2.50g（AOE 可翻倍效率） |

#### 玩家配置

- **武器槽**：3 个（`weapons` 数组最大长度 3）
- **弹药池**：`ammo_reserve: Dictionary[StringName, int]`（6 个弹种 + 手雷独立）
- **初始配装**：手托手枪-小口径（弹匣 12 / 备弹 36 进手枪弹池）+ EMP 控制手雷 ×1
- **切枪**：保留 `weapon_toggle`，3 槽循环
- **替换武器时弹药保留**：弹药池按弹种维度，不因持枪变化而丢失

#### 武器耐久度

每把枪有 `durability_max`，每扣一次扳机耐久减 1，归零后枪**爆掉**——播放小爆炸粒子特效后直接从武器槽中移除、槽位自动腾空。

- 耐久归零 → 自动触发 `_on_weapon_broken(current_index)`：播放火花/碎片粒子 → 从 `weapons` + `weapon_durability` 数组中移除 → 自动切到下一把（若还剩有枪）或空手
- 耐久度不自动恢复、不可修复（v1）
- 商店/宝箱获得的新枪满耐久
- 耐久显示在 HUD 武器栏每把枪图标下方（进度条或百分比），低耐久（≤20%）变红
- 设计意图：枪是消耗品，鼓励多枪轮换 + 频繁换枪，而非一把枪用到死

#### 武器丢弃与拾取

- **主动丢弃**：新增输入动作 `drop_weapon`（默认 **X 键**），丢弃当前手持武器到脚下
- **地面拾取**：丢弃的枪在地面生成一个旋转的拾取物（`Area3D` + 小武器模型），玩家走过有**空槽**（<3 把）时自动捡起
- 3 槽全满时走过不拾取（需先主动丢一把再捡，或等某把枪耐久爆掉自动腾槽）
- **允许持有重复武器**：3 个槽位可装同一把枪（如 3 把微型冲锋枪），无排重限制
- 商店购买时若满槽 → 保持替换对话框流程（同原有设计）
- 拾取的枪保留其当前耐久度（不是满耐久——公平性：别人用过的就那样）

#### 键位调整

| 功能 | 旧键 | 新键 | 原因 |
|------|------|------|------|
| 挣扎 | G | **H** | G 让给手雷投掷 |
| 手雷投掷 | — | **G** | 新增 |
| 丢枪 | — | **X** | 新增 |

#### 手雷

- 独立槽位（不占武器 3 槽），最多携带 5 颗
- EMP 控制手雷：范围减速/沉默敌人（由烟雾手雷 GLB 改制）
- 破片手雷：范围爆炸伤害（由破片手雷 GLB 改制）
- 操作：新增输入动作 `throw_grenade`（G 键），按住切换类型、松开投掷
- 初始：EMP ×1
- 获取：商店随机刷（EMP 25 金 / 破片 20 金）、宝箱概率掉落

### 7. RunDirector 数据驱动化

当前 `MONSTER_COST`、`_available_types`、`_reward_for`、`_monster_scenes` 全为硬编码。重构为数据驱动：

```gdscript
# 敌人配置表（单一来源）
const ENEMY_CONFIG := {
    &"普通女":  { "cost": 5,  "reward": 5,  "min_wave": 1,  "scene": preload("res://objects/enemy_normal_female.tscn") },
    &"普通黑女": { "cost": 5,  "reward": 5,  "min_wave": 1,  "scene": preload("...") },
    # ... 全部 16 个
}
```

`_available_types(wave)`、`_reward_for(type)`、`_spawn_monster` 均从该字典推导，不加新 if/elif 分支。
