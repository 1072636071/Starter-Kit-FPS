# ADR 009: 竞技场运行结构 —— 单固定竞技场 + 无尽递增波次

## 决策

一局游戏采用 **方案 A：单固定竞技场 + 无尽递增波次（Endless Escalating Waves）**。玩家在**一个固定的竞技场**中作战；怪物以**离散波次（Wave）**成组刷出，波与波之间**难度递增（Escalation）**；每波清空后的**波次间歇（Intermission）**是玩家消费金币 / 经验（买子弹、升级）的窗口。玩家死亡即本局结束。

## 背景

用户构想的肉鸽竞技场游戏核心循环：击杀怪物 → 掉落金币 + 经验（小概率血包）→ 金币买子弹、经验升级 → 角色有血量 + 护盾（护盾自动恢复、血量靠血包）。需要决定"一局（run）"的骨架形态：是单场持续、分段房间、还是开放刷怪。这一定义是所有后续系统（刷怪、商店、升级、护盾、掉落）的时间轴锚点。

## 替代方案

| 方案 | 描述 | 否决原因 |
|------|------|----------|
| **A. 单竞技场 + 无尽波次（选中）** | 固定竞技场，怪物成波刷出且逐波变强，波间间歇消费 | 最贴合"竞技场 / 肉鸽"语义；金币买子弹、经验升级天然嵌入"波次间歇"节奏；结构最简单，无需多房间 / 传送逻辑 |
| B. 分段竞技场 | 清房间 → 传送门进下一更难房间，关间进商店 | 更"关卡化"，但需多房间 / 传送 / 进度逻辑，v1 过重 |
| C. 开放持续刷怪 | 无离散波次，怪持续刷、难度随时间升，商店为走动摊位 | 最自由但最难平衡；无"间歇"窗口，金币 / 经验消费时机模糊 |

## 影响

- 需要一个 **Wave / Spawn 控制器**：负责刷怪、波次推进、难度曲线（Escalation）。
- 需要一个 **Intermission 状态**：停止刷怪、开放消费窗口（商店 / 升级 UI）。
- 死亡处理从 `player.gd` 当前的 `get_tree().reload_current_scene()`（瞬时重置、无界面）改为"本局结束 → 游戏结束界面 / 重开"（具体见后续 grill 决策）。
- 金币、经验、护盾、血包等系统都以该结构为时间轴锚点（详见 CONTEXT.md「Roguelike 竞技场系统」）。
