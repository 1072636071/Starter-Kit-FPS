# ADR 026: 小地图改为玩家中心局部跟随（取代全图覆盖）

## 状态

已决策（grill 会话，2026-07-26）。取代 ADR 007「缩放」子决策中的"全图覆盖 ~160m"。

## 决策

小地图从**全图固定俯视**改为**玩家中心局部跟随（player-centered follow）**：

- 俯视相机跟随玩家 x/z（不再固定在世界原点）；仍北朝上、仍正交投影。
- 只渲染玩家周围一圈，覆盖范围由**可配置 `View Radius`** 决定（初值 80m）。
- 图外敌人不画在图内，改用**屏外威胁指示（Off-Screen Indicator）**在圆形边缘表示其方向。
- 保住原"随时知道敌人在哪"的核心价值（原"敌人全显示"的精神以屏外箭头形式保留）。

## 背景

地图已扩展，且未来尺寸**不确定、可能继续增长**（用户确认）。原全图方案在 `minimap.gd` 硬编码 `WORLD_HALF=80`（±80 / 160m），`main.tscn` 的 `MinimapCamera` `size=160` 固定不动、位于原点上方。

地图超出 ±80 后：
- 地形不在正交视锥内 → 俯视渲染裁掉；
- 实体 blip 被 `_draw` 的圆形裁剪（`pixel.distance_to(center) > clip_r` 跳过）丢弃 → 不显示。

即"无法完整展示当前地图"。且尺寸未知使"改大常数 / 改大相机 size"路线不可行：每次扩张都需回头改常数+相机、地图越大 blip 越密越小、可读性崩。

## 替代方案

| 方案 | 描述 | 否决原因 |
|------|------|----------|
| A. 玩家中心局部跟随（**选中**） | 相机跟随玩家，局部渲染 + 屏外箭头 | 尺寸任意/增长都鲁棒；复用现有 SubViewport+2D 叠加，改动最小；保留"知敌位置"价值 |
| B. 全图缩放、view radius 可配置 | 仍全图俯视，仅把 160 改大 | 尺寸不确定 → 迟早再撑爆；大图下 blip 密集不可读 |
| C. 混合：全图缩略 + 玩家中心详情 | 右上角小全图 + 局部详情层 | 最稳但 UI 最复杂、占屏、实现重，v1 过度工程 |

## 影响 / 变更点（vs ADR 007）

- `MinimapCamera`：从固定原点上方 `(0,80,0)` → 每帧 `global_position.x/z = player.global_position.x/z`（y 仍高处朝下）。
- `minimap.gd`：`const WORLD_HALF := 80.0` 硬编码 → 可配置 `view_radius`（运行时 `@export` 或常量），投影改相对玩家：`uv = (world_pos.xz - player_pos.xz + view_radius) / (2 × view_radius)`。
- ADR 007「缩放」行的"全图覆盖 ~160m"被本 ADR 取代。
- "敌人全显示"精神保留，但图外敌人改为屏外箭头表示（见 Off-Screen Indicator）。
- 渲染方案本身（SubViewport + 正交俯视相机 + 2D 叠加 blip + 圆形遮罩）不变，仍见 ADR 007。

## 待定细节（grill 中，逐条确认后回填）

- **Q3 View Radius（已定）**：**80m**（即 ±80，与旧全图半幅一致），保证局部地形清晰度与 blip 大小不变，迁移成本最低。设为可配置初值，便于未来按需调大。
- **Q4 朝向（已定）**：保持 **north-up**（北朝上），与 ADR 007 一致。相机 x/z 跟随但朝向不转——地面永远稳定，玩家用三角形箭头在圆心表示 facing。无迁移成本、无眩晕风险。
- **Q5 屏外威胁指示（已定）**：**方向箭头 + 颜色区分，v1 最简**。每个图外敌人在圆形边缘对应方向画一个小三角形箭头（指离圆心），按类型着色（近战=红、远程=黄，与 blip 一致）。不合并分组、不显示距离数字、不显示数量——"那边有红色威胁"即足够。多只敌人同一方向时箭头自然叠加变粗 = 直观表示密集度。
- **Q6 缩放交互（已定）**：**v1 不做 zoom**（固定 80m）。玩家中心跟随 + 屏外箭头已覆盖核心需求，zoom 是锦上添花。留待未来收集手感数据后再评估。

## 反模式警示

- 切勿恢复"写死 WORLD_HALF 跟随地图尺寸改"——尺寸不确定，必须由可配置 `view_radius` 与相机 follow 解耦。
- 切勿因"全图"旧决策残留而让相机不跟随——那是本次要修的核心问题。
