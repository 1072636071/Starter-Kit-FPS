# 警戒翻倍 + 三级货币背包系统 — 规格文档

**日期**: 2026-07-25
**状态**: ready-for-agent
**关联 ADR**: 023（三级货币+背包）、017（敌人AI）、022（武器弹药扩展）
**领域词汇**: CONTEXT.md「Chain Aggro / Gold / Silver / Copper / Backpack / Ammo Slot」

## 问题陈述

当前游戏存在两个体验问题：

1. **敌人感知太弱**——近战怪 8m、远程怪 12m 外就看不见玩家，玩家可轻松绕开大部分战斗，竞技场压力不足。
2. **子弹感觉昂贵**——单一金币货币下，最低消费 1 金 = 24 发手枪弹，玩家惜弹如金不敢随意开火；弹药管理维度单一（仅有 `ammo_reserve` 备弹池），缺乏资源规划深度。

## 解决方案

### Part A：警戒范围翻倍

所有敌人感知参数全局 ×2。玩家进入竞技场后，敌人从更远距离发现玩家、追踪更远、声音传播更广，显著提升战斗密度和紧张感。

### Part B：三级货币 + 背包弹药系统

引入银币和铜币，汇率 1金=100银=10000铜。弹药按铜币定价（单发手枪弹=1铜），使子弹成为廉价消耗品。

同时引入重量制背包系统和 10 个备弹槽，形成三层弹药流：

```
背包（重量制，T键慢速补货）→ 备弹槽（10个，R键快速换弹）→ 弹匣
```

玩家需在波次间歇规划弹药分配——背包里子弹充足，但补到身上的过程有风险（1.5s 整理动画），创造"贪 vs 安全"的决策点。

## 用户故事

### Part A：警戒翻倍

1. 作为玩家，我希望敌人在更远距离就能发现我，以便竞技场始终有压迫感，而非可以安全绕路。
2. 作为玩家，我希望敌人枪声能传播更远，以便我的每次交火都可能引来更多敌人，增加战术复杂度。
3. 作为玩家，我希望飞行敌人也能从更远距离追踪我，以便空中威胁不会轻易被我甩开。

### Part B：货币系统

4. 作为玩家，我希望看到金银铜三种货币显示在 HUD 上，以便直观了解自己的财富层级。
5. 作为玩家，我希望击杀怪物掉落的铜币能自动进位成银币和金币显示，以便我不需要心算大数字。
6. 作为玩家，我希望在商店用铜币购买廉价弹药捆，以便我感受到"子弹不值钱，尽情开火"。
7. 作为玩家，我希望用银币购买手雷、用金币购买武器，以便每种货币有明确的消费出口。
8. 作为玩家，我希望经济系统鼓励我频繁使用弹药而非囤积，以便战斗节奏更快、更有爽感。

### Part B：背包系统

9. 作为玩家，我希望拥有一个重量制背包存放子弹、枪械和血包，以便我在波次间歇有充足的续航储备。
10. 作为玩家，我希望背包不受格子上限约束，仅受重量限制，以便我能带大量廉价子弹（手枪弹很轻）而无需纠结格子管理。
11. 作为玩家，我希望不同物品有不同的重量，以便我需要权衡"带更多子弹还是带备用枪"。
12. 作为玩家，我希望通过升级卡提升背包负重上限，以便后期能携带更多物资应对高波次。

### Part B：备弹槽

13. 作为玩家，我希望身上有 10 个快速取用的备弹槽，以便战斗中按 R 键快速换弹。
14. 作为玩家，我希望自由分配备弹槽的弹药类型，以便我可以根据当前持有的武器定制弹药配置（如 4 个手枪弹槽 + 3 个步枪弹槽 + 3 个霰弹槽）。
15. 作为玩家，我希望每槽容量等于对应武器的一个弹匣量，以便我直观理解"还有几个弹匣可打"。
16. 作为玩家，我希望备弹槽打空后必须从背包补货，以便弹药管理有"战斗续航"和"战略储备"两层深度。

### Part B：背包 UI 与 T 键

17. 作为玩家，我希望按 T 键打开全屏背包界面（暂停游戏），以便在安全时从容整理物资。
18. 作为玩家，我希望在背包 UI 中将物品拖拽或点击分配到备弹槽，以便操作直观。
19. 作为玩家，我希望关闭背包 UI 后有一个短暂的"整理"动画（约 1.5 秒），期间我可移动但不能射击，以便补货有风险代价。
20. 作为玩家，我希望背包 UI 在暂停时也能正常交互，以便与商店、升级等暂停系统兼容。

### Part B：商店与 HUD 联动

21. 作为玩家，我希望商店弹药价格以铜币显示、手雷以银币显示、武器以金币显示，以便价格层级一目了然。
22. 作为玩家，我希望 HUD 上的货币数量随击杀奖励和消费实时更新，以便我随时知道还能买什么。

## 实现决策

### 货币核心

- `RunDirector` 内部统一用铜币（`copper: int`）存储，所有加减操作以铜币为单位
- `currency_changed(copper: int)` 信号替代 `gold_changed(gold: int)`
- 货币显示函数 `format_currency(copper) -> String`："1金23银45铜"
- 击杀奖励改为铜币：近战 500、远程 800、飞行 1000
- `add_copper(amount)` / `spend_copper(amount) -> bool` 替代 `add_gold` / `spend_gold`
- 宝箱奖励（金币大礼包）按汇率换算：`(20 + 5×wave) × 100` 铜

### 背包数据模型

- `Player` 新增：
  - `backpack_items: Dictionary` — `{item_id: {type, count, weight_per_unit}}` 或简化结构
  - `backpack_weight: float` — 当前总重量
  - `backpack_max_weight: float = 80.0` — 上限
  - `ammo_slots: Array[Dictionary]` — 长度 10，每项 `{ammo_type: StringName, count: int}`，count 最大为对应弹匣容量
- 物品重量表（硬编码常量）：
  - 手枪弹 0.01/发，步枪弹 0.02/发，霰弹 0.04/发
  - 狙击弹 0.08/发，能量电池 0.03/发，榴弹 0.10/发
  - 枪械整把 3–8，血包 1.5

### 备弹槽换弹逻辑

- 现有 `action_reload()` 改为消费备弹槽：找到第一个匹配 `ammo_type` 且有剩余容量的槽 → 从中扣 `magazine_size` → 填入弹匣
- 若所有同类型槽为空，提示"备弹槽已空，按 T 从背包补货"
- 换弹速度不变（仍用 `reload_time`）

### T 键背包 UI

- 新增输入动作 `backpack`，绑定 T 键
- 新建 `BackpackUI`（Control，`PROCESS_MODE_WHEN_PAUSED`）
- 布局：左侧背包物品列表（按类型分组，显示名称/数量/重量），右侧 10 个备弹槽（显示类型/剩余弹匣数）
- 交互：点击背包中的弹药堆 → 点击目标备弹槽 → 转移一个弹匣的量（若背包不足则提示）
- 关闭 UI 后启动 1.5s 整理计时器，期间 `_is_packing = true`，禁止射击和换弹，允许移动

### 商店重新定价

弹药捆价格（铜币）：
- 手枪弹捆 24 发 → 24 铜
- 步枪弹捆 20 发 → 60 铜
- 霰弹捆 8 发 → 80 铜
- 狙击弹捆 4 发 → 80 铜
- 能量电池捆 12 发 → 60 铜
- 榴弹捆 2 发 → 100 铜

手雷价格（银币）：EMP 3 银，破片 2 银

武器价格（金币）：原 30–175 ÷10 → 3–18 金

### 升级池扩展

新增第七项：
- `id: "backpack_weight"`, `name: "+10 背包负重"`, `desc: "背包负重上限 +10"`

### 警戒范围翻倍

变更点（均为 `@export` 默认值）：
- `monster_base.gd`: `awareness_range 8→16`, `chase_range 25→50`, `DEATH_ALERT_RADIUS 20→40`
- `monster_ranged.gd`: `SHOOT_ALERT_RADIUS 25→50`
- `enemy.gd`: `chase_range 35→70`
- `player.gd` 中玩家开枪 `emit_alert` 半径 30→60

## 测试决策

### 测试原则

- 仅测试外部行为（怪物行为变化、货币显示、背包操作流程），不测内部实现
- 复用现有烟测场景和测试基础设施

### 测试场景

- **警戒翻倍**：复用 `tests/test_smoke_enemies.tscn` / `tests/test_smoke_waves.tscn`，验证怪物在翻倍距离进入 CHASE
- **货币显示**：在 RunDirector 测试中注入固定数量铜币，验证 `format_currency()` 输出正确金银铜格式
- **背包操作**：新建 `tests/test_backpack_ui.tscn`，验证添加物品→重量计算→T键打开→拖拽分配→备弹槽更新→关闭整理动画的完整流程
- **商店价格**：复用 `tests/test_shop_ui_redesign.tscn`，验证弹药价格以铜币显示、手雷以银币显示、武器以金币显示
- **备弹槽换弹**：新建 `tests/test_ammo_slot_reload.tscn`，验证消费备弹槽→弹匣填充→槽空→无法换弹→补货后可换弹的完整链路
