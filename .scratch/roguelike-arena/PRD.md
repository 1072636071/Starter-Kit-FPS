# PRD — Roguelite Arena（肉鸽竞技场）

> 本规格综合自 grill-with-docs 会话（见 `docs/adr/009`–`014` 与 `CONTEXT.md`「Roguelike 竞技场系统」术语表）。所有设计决策已落定，本文档仅做综合，不另做访谈。

## 问题陈述

当前项目是一个裸 FPS 沙盒：玩家能射击 / 近战怪物，但**击杀没有任何后果**——没有经济、没有成长、没有生存层（只有一个平的血量池），死亡是 `reload_current_scene()` 的瞬时重置、无任何反馈。用户希望把它变成一局**肉鸽竞技场**游戏：击杀怪物 → 获得金币 + 经验（小概率血包）→ 金币买子弹、经验升级 → 在递增的波次里尽可能久地存活。

## 解决方案

在现有 FPS 之上叠加一套肉鸽竞技场循环：

- **单固定竞技场 + 无尽递增波次**：怪物按波成组刷出，逐波更强；波间手动确认开下一波。
- **护盾层**：伤害先扣护盾、溢出才扣血量；护盾脱战延时后自动恢复，血量只靠血包。
- **击杀奖励**：怪物死亡掉金币 + 经验（按类型分档），小概率掉血包。
- **子弹商店**：竞技场里一个固定物理摊位，走过去即暂停、按金价买各枪备弹。
- **升级三选一**：经验跨阈值即时暂停，从升级池抽 3 选 1。
- **游戏结束**：血量归零 → 结算界面（战绩）+ 重开。

## 用户故事

1. 作为玩家，我想要在**单个固定竞技场**里打**无尽递增的波次**，以便每一局都是自洽的生存挑战。
2. 作为玩家，我想要一个**护盾层**在血量之前吸收伤害，并在最后一次受击后延时自动恢复，以便我有一个可再生缓冲、不必时刻依赖血包。
3. 作为玩家，我想要**血量只靠血包恢复**（不自动回），以便护盾/血包的分工形成真实的资源管理。
4. 作为玩家，我想要怪物死亡时掉落**金币与经验**，以便击杀被奖励。
5. 作为玩家，我想要**更强的怪物类型掉落更多金币/经验**（近战 < 远程 < 飞行），以便更难的波次更值得打。
6. 作为玩家，我想要怪物死亡有**小概率掉血包**，以便在血量低时有一条活路。
7. 作为玩家，我想要在竞技场的**子弹商店摊位**花金币补备弹，以便一局内可持续作战。
8. 作为玩家，我想要**走进商店摊位就暂停游戏并打开购买 UI**，以便购买是安全、刻意的。
9. 作为玩家，我想要**每把枪有不同的单发金价**（强枪更贵），以便弹药经济有层次。
10. 作为玩家，我想要金币购买受每枪 `max_reserve` **封顶**，以便不能无限囤弹。
11. 作为玩家，我想要经验跨阈值时**即时暂停并弹三选一升级卡**，以便变强有即时反馈。
12. 作为玩家，我想要升级卡从**升级池随机抽 3 个不重复**让我选 1，以便 build 靠随机堆叠、有构筑感。
13. 作为玩家，我想要**升级阈值随等级递增**（首级 20，之后 ×1.3），以便后期不会瞬间铺满 build。
14. 作为玩家，我想要波次**分数预算随波递增**（第 N 波 `60 × 1.2^(N-1)` 分）且**类型分阶段解锁**（1–3 波纯近战、4 波起远程、7 波起飞行），以便竞技场持续变难。
15. 作为玩家，我想要每波怪物在**波开始时一次性全刷**、我**全灭**后才算清场，以便节奏清晰。
16. 作为玩家，我想要波间**手动确认**才开始下一波，以便我能先去商店补弹、消化升级卡。
17. 作为玩家，我想要死亡时看到**游戏结束界面**，展示存活波数 / 击杀数 / 累计金币 / 达到等级，并提供**重开一局**按钮，以便一局有始有终。
18. 作为玩家，我想要重开即**全新一局**（金币 / 经验 / 护盾 / 弹药 / 升级全重置），以便每局独立。

## 实现决策

下列决策均已在 ADR / grill 会话中落定，实施时直接采用；所有初值均为 `@export` 可调。

- **运行结构（ADR 009）**：单固定竞技场 + 无尽递增波次；波间为无刷怪停顿，下一波由玩家手动确认（Q6）。
- **护盾吸收（ADR 010）**：`damage(amount)` 改为先减 `shield`、溢出再减 `health`；护盾在最后一次受击后 `shield_regen_delay = 3s` 开始以 `shield_regen_rate = 10/s` 恢复（战斗中亦可回）；`shield_max = 50`；死亡判定仍为 `health <= 0`（护盾归零不致死）。需在 `Player` 暴露 `shield_updated` 信号。
- **升级三选一（ADR 011）**：XP 跨阈值触发 Level Up，从升级池随机抽 3 不重复，玩家选 1 即时生效（本局内永久）。触发时机为**即时暂停**（Q5），非延迟到间歇。
- **金币消费（ADR 022 修改 ADR 012）**：金币在商店消费：购买武器（30–180 金/把）、弹药捆（12–20 金/捆）、手雷（25–30 金/颗）。~~按"发"买备弹已废弃~~。
- **商店为物理摊位（ADR 013 + ADR 022 扩展）**：竞技场中固定位置的 `Shop Station`；走入即暂停并开三区购买 UI（武器区随机 3 把枪 / 弹药区随机 3–4 种弹药捆 / 手雷区随机 1–2 种手雷）。金币消费不限于间歇。
- **击杀奖励（ADR 022 修改）**：16 角色分档，成本=奖励——普通女/普通黑女=5、警察=6、游戏宅=8、律师/日本艺妓=10、研究员-老人/牛仔=12、独眼牛仔/猎人=14、化学人=15、健壮男=16、机器人-男电=18、机器人-女心=20、驯兽师=22、忍者=25；血包掉率 10%；**不随波缩放**。
- **难度递增（ADR 022 修改 ADR 018）**：分数预算 `60 × 1.2^(N-1)` 不变；类型分 5 阶段解锁（1–3/4–6/7–9/10–12/13+），共 16 种角色敌人。参见 [ADR 022](file:///g:/work/Starter-Kit-FPS/docs/adr/022-enemy-weapon-expansion.md)。
- **游戏结束（ADR 014）**：`health <= 0` → 冻结 → 结算界面（存活波数 / 击杀数 / 累计金币 / 达到等级）→ 重开；取代原 `reload_current_scene()` 裸重置。明确**不做**跨局元进度（meta-progression）。
- **升级阈值（Q10）**：首级 20 XP，之后每级 ×1.3（20→26→34→44…）。
- **升级池初版（ADR 011 列出的待细化项）**：`+20 最大血量`、`+5 护盾恢复速率`、`+15% 伤害`、`+0.5 移动速度`、`+1 每把枪备弹上限`、`-10% 换弹时间`（"备弹上限"影响所有弹种而非单枪）。
- **弹药类型（ADR 022）**：6 种弹药——手枪弹、步枪弹、霰弹、狙击弹、能量电池、榴弹。弹药按类型池化（`ammo_reserve: Dictionary`），同一弹种共享。商店按捆售卖。15 把枪按弹种分类。
- **武器槽 + 手雷槽（ADR 022）**：玩家最多带 3 把枪。初始配装：手托手枪-小口径 + 2 空槽。手雷独立槽，最多 5 颗，初始 EMP×1。
- **宝箱扩展（ADR 022 扩展 issue 08）**：奖励池从 4 项增至 6 项（+随机武器、+手雷补给）。

### 测试 Seam（关键架构点，请确认是否符合预期）

- **最高层 seam = 新增 `RunDirector`（竞技场运行编排器）**：拥有本局状态（波次、金币、经验、等级、run stats）并暴露信号 `wave_started` / `wave_cleared` / `gold_changed` / `xp_changed` / `level_up_offered(choices)` / `game_over(stats)`。它组合下面两个既有/最小新 seam。测试主要驱动 `RunDirector` 的外部状态与信号，不触碰内部。
- **既有 seam = `Player.damage(amount)`**：护盾/血量逻辑的唯一入口（ADR 010 在此修改）。测试通过调用 `player.damage(x)` 断言护盾/血量数值与 `shield_updated` / `health_updated` 信号。
- **最小新 seam = 怪物 `died(type)` 信号**：现有怪物在 `health <= 0` 时 `destroy()` → `queue_free()`，**不发射任何死亡信号**。需在 `damage()`/`destroy()` 中新增 `signal died(monster_type: StringName)`，由 `RunDirector` 监听以结算击杀奖励。这是本功能唯一必须新建的底层 seam。

> 若你希望换一个编排层（例如把 `RunDirector` 做成 autoload 而非 `Main` 子节点，或把怪物死亡改由 `RunDirector` 轮询检测而非信号），请在此指出——否则按上述 seam 实施。

## 测试决策

- **只测外部行为**：通过上述 `RunDirector` 信号与 `Player` 状态断言，不测内部计时器 / Tween 实现细节。
- **被测模块**：`RunDirector`（波次推进、奖励结算、升级触发、游戏结束）、`Player`（护盾优先吸收 + 延时恢复 + 血量只靠血包）、怪物（`died` 信号正确携带类型）、`Shop Station`（走入暂停 + 购买扣金币加备弹封顶）、升级流程（阈值递增 + 三选一 apply）、Game Over（死亡结算 + 重开重置）。
- **概率类测试**：血包掉率、抽 3 不重复等需**可注入种子的 RNG**（或测试钩子），断言统计分布而非单次结果。
- **先例**：沿用 `tests/` 下既有场景测试风格（`preload("res://…tscn").instantiate()` → `get_node_or_null` → `_check(cond, msg)` → 打印 `[TEST] PASS/FAIL` 并 `quit(1)` 失败；以 `godot --headless --path . res://tests/test_xxx.tscn` 运行）。新测试放入 `tests/` 并命名 `test_arena_*.gd`。

## 超出范围

- 跨局元进度（meta-progression / 解锁永久成长）——ADR 014 明确 v1 不做。
- 多竞技场 / 分段房间 / 传送门（ADR 009 已否决 B/C）。
- 多人 / 联机。
- 丧尸、狂暴丧尸两个角色（用户明确排除，留作未来拓展）。
- cube-pets 独立敌种（仅作为驯兽师 SummonPet 模块的召唤物）。
- 武器配件系统（瞄具/消音器/弹匣，素材有但机制规划暂不做）。
- 新增音效素材（挥砍/升级/商店音效等）；复用现有音效，缺素材的暂不做。
