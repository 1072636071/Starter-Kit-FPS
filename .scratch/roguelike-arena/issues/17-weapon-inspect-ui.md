# 17 — 武器检视与对比 UI

Status: ready-for-agent
Type: task
Refs: ADR 022, issues 15

## 问题陈述

游戏有 20 把枪（18 新 + 2 现役），每把枪有 15+ 个属性（伤害、射速、精度、弹匣容量、备弹上限、换弹时间、弹药类型、耐久度、售价、角色定位、可靠性等），但玩家**在游戏中看不到这些属性**。商店 UI 虽然展示了部分属性，但只在商店打开时可见，且不提供对比功能。玩家无法在战斗中对比手中 3 把枪的优劣、判断是否该替换、理解每把枪的定位差异。

## 解决方案

新增武器检视 UI：按 TAB 键打开全屏面板，三张卡片并排展示 3 个武器槽的完整属性。核心差异化能力是**对比模式**——点击一张卡片将其固定为"参考"，其余卡片自动标注相对于参考的优劣差异。

## 用户故事

1. 作为玩家，我想要在游戏中随时按 TAB 键查看手中所有武器的完整属性，以便做出装备决策。
2. 作为玩家，我想要每张武器卡片显示：武器名称、角色定位、可靠性星级、弹药类型、DPS、伤害值、射速（RPM）、精度条（含文字评级）、当前弹药状态（弹匣/备弹）、弹匣容量、备弹上限、换弹时间、耐久度条、售价，以便一卡了解武器全貌。
3. 作为玩家，我想要当前装备的武器卡片以金色边框高亮，以便一眼分辨正在使用的武器。
4. 作为玩家，我想要点击一张武器卡片将其固定为"对比参考"（蓝色边框），其余卡片自动显示相对于参考的差异——更优的属性显示绿色 ▲、更差的显示红色 ▼、持平的显示灰色 =，以便快速判断三把枪的优劣。
5. 作为玩家，我想要再次点击已固定的卡片取消对比、恢复正常显示，以便灵活切换对比视角。
6. 作为玩家，我想要按 ESC 键关闭武器检视面板，回到正常游戏，以便快速返回战斗。
7. 作为玩家，我想要武器检视面板中的弹药数字在我开火时实时更新，以便信息始终准确。
8. 作为玩家，我想要武器检视面板中的当前武器边框在切换武器（Q / 滚轮）时同步更新，以便始终知道哪把枪是激活的。
9. 作为玩家，我想要武器检视面板在商店、升级、死亡等暂停 UI 打开时自动关闭，避免多窗口冲突。
10. 作为玩家，我想要空武器槽显示为"（空槽）"提示卡片而非崩溃或留白，以便了解槽位状态。
11. 作为玩家，我想要耐久度条的颜色直观反映武器可靠性：绿色（耐久 ≥200，极高）、黄色（耐久 85–199，一般）、红色（耐久 ≤85，易损），以便一眼判断该枪还能用多久。
12. 作为玩家，我想要精度条的填充和颜色直观反映武器散布：绿色（spread < 1.0，高精度）、黄色（spread 1.0–2.5，中等）、红色（spread > 2.5，低精度），并附文字评级（极高/高/中/低/极低），以便快速判断中远距离能力。
13. 作为玩家，我想要对比模式下精度条和耐久条也反映被对比武器的实际填充量（而非与参考相同的 fill），以便对比时视觉信息不丢失。
14. 作为玩家，我想要空槽位不可被点击为对比参考，以便操作符合直觉。

## 实现决策

### Weapon 资源身份字段

`Weapon` 资源（`scripts/weapon.gd`）新增加 `@export_subgroup("Identity (ADR 022)")` 六个字段：

- `ammo_type: StringName` — 弹药类型（手枪弹 / 步枪弹 / 霰弹 / 狙击弹 / 能量电池 / 榴弹）
- `weapon_cost: int` — 商店售价（金），默认 30
- `durability_max: int` — 最大耐久（扣扳机次数），默认 150
- `role_title: String` — 角色定位描述，如"入门可靠型"
- `role_features: String` — 核心特征描述
- `reliability_stars: int` — 可靠性星级 1–3

### 武器检视 UI 模块

新建 `scripts/weapon_inspect_ui.gd`（`extends Control`），纯代码构建 UI（无 `.tscn` 依赖），暴露公共 API：

- `open(player: Node3D)` — 读 `player.weapons` / `player.magazine` / `player.reserve` 构建三张卡片
- `close()` — 隐藏并恢复鼠标捕获（游戏未暂停时）
- `refresh_ammo()` — HUD 在 `ammo_updated` 信号时调用，更新弹药数字和当前武器边框
- `is_open() -> bool` — 状态查询

`_process` 中检测 `get_tree().paused` 自动关闭，确保与商店/升级/死亡 UI 不冲突。

每张卡片显示以下属性行：

| 行 | 内容 | 格式 |
|----|------|------|
| 武器名 | `display_name` | 白色 22pt 居中 |
| 定位+可靠性 | `role_title  ★★★` | 灰色 15pt |
| 弹药类型 | 弹药中文名 | 蓝色 |
| DPS | `damage × shot_count / cooldown` | 白色 |
| 伤害 | `25` 或 `8 × 6`（霰弹多弹丸） | 白色 |
| 射速 | `60 / cooldown` RPM | 白色 |
| 精度条 | 填充 `(5.0 - spread) / 5.0` + 文字评级 | 绿/黄/红 |
| 弹药状态 | `magazine / reserve` 实时值 | 白色，实时刷新 |
| 弹匣容量 | `magazine_size` 发 | 白色 |
| 备弹上限 | `max_reserve` 发 | 白色 |
| 换弹时间 | `reload_time` s | 白色 |
| 耐久条 | 满条 + `durability_max` 数字 | 绿/黄/红（阈值 200/85） |
| 售价 | `weapon_cost` 金 | 金色 |
| 当前装备标记 | "◆ 当前装备" | 仅当前武器槽显示 |

### 对比模式

点击卡片 → `_on_card_clicked(slot)` 设置 `_pinned_index`。若已固定同一张卡则取消（`_pinned_index = -1`）。

对比逻辑：`_refresh_compare_indicators()` 遍历所有非参考卡片，对每个可比属性计算差值。方向规则：

- **正向指标（越大越好）**：DPS、伤害、弹匣、备弹、耐久
- **反向指标（越小越好）**：cooldown/射速、spread/精度、reload_time、weapon_cost（价格便宜更好）
- 反向指标在比较时取负值，统一为 `val > ref_val → 更好`

空槽位卡片不受对比影响。

### HUD 集成

`scripts/hud.gd` 新增：

- `_build_weapon_inspect_ui()` — 实例化场景 + 绑定 `closed` 信号 + 初始隐藏
- `_can_open_weapon_inspect() -> bool` — 检查 `get_tree().paused` + player 有效 + 无 shop_ui 可见
- `_unhandled_input` — 检测 `KEY_TAB` pressed，toggle open/close
- `_on_ammo_updated` 末尾调用 `refresh_ammo()` 同步弹药数据显示

### 耐久与定价设计原则（ADR 022 更新）

耐久度非均匀套公式设计，每把枪独立设定：

- **固定消耗**：每次扣扳机 -1 耐久（霰弹齐射 / 双管能量双发均只计 1 次）
- **高射速枪需要更多总耐久**（机枪 280 发但 0.08s 射速仅 ~22s 连射）
- **爆发型武器收紧**（重型狙击仅 35 发，每发都是决策）

可靠性阈值：★★★ ≥200（5 把）、★★☆ 86–199（8 把）、★☆☆ ≤85（5 把）

定价 = 战斗力 + 弹药经济性调节：弹药便宜的枪（手枪弹 0.04g/发）定价可略激进，弹药贵的枪（狙击弹 1g/发、榴弹 2.5g/发）适当压价。

各枪最终参数见表（18 把，详见 ADR 022 武器参数表）。

### 场景文件

新建 `scenes/weapon_inspect_ui.tscn`（最小场景：`WeaponInspectUI` 根节点绑定脚本）。由 HUD 在 `_ready` 中实例化并 `add_child`。

## 测试决策

### 测试策略

- **Weapon 身份字段**：纯数据测试，创建 `.tres` 后断言各字段值
- **WeaponInspectUI**：不依赖完整场景树，编写测试脚本实例化 UI → 构造 mock player（含 weapon 数组、magazine/reserve 数组）→ 调用 `open(player)` → 断言卡片 label 文本和颜色
- **对比逻辑**：`_refresh_compare_indicators` 的对比方向正确性可通过构造两把参数已知的武器来验证
- **HUD TAB 输入**：模拟 `InputEventKey(KEY_TAB)` → 断言 `is_open()` / `visible` 状态切换
- **自动关闭**：模拟 `get_tree().paused = true` → 断言 UI 自动 close

### 测试先例

项目中已有 `tests/test_run_director.gd`、`tests/test_monster_fall_death.gd` 等测试文件，沿用相同的 `extends Node` + `func test_*()` + `assert_*()` 模式。测试场景置于 `tests/` 目录。

## 超出范围

- 武器检视 UI 中不包含武器模型 3D 预览（v1 仅文本属性卡片）
- 不包含按属性排序 / 筛选功能
- 不包含武器图鉴（查看从未持有过的武器）
- 不包含在商店 UI 中嵌入对比功能（商店有独立的展示逻辑）
- 不修改现有 HUD 右下角弹药列表的显示方式

## 补充说明

- TAB 键与 Godot 引擎默认的 `mouse_capture_exit` 输入不冲突（我们自行处理 `_unhandled_input`，不依赖默认动作）
- 武器检视 UI 的 `PROCESS_MODE_PAUSABLE` 确保暂停时不消耗帧资源
- 对比模式下，精度条和耐久条的颜色也跟随被对比武器的实际属性变化（非仅数字变化）
- `Weapon` 资源的 `gold_cost_per_bullet` 字段在 ADR 022 中已废弃（改为按弹药类型买捆包），但保留字段不做删除以避免 `.tres` 加载报错
